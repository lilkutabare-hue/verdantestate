# План: медиа сайта там, где они открываются из России всегда (21.10.2026)

Требование владельца: сайт работает в России всегда, в остальных странах и у русских через VPN — почти всегда. Инструменты любые.

## 1. Что не так сейчас

- Медиа для блоков Тильды (267 файлов, 28 МБ: 202 кадра пролёта, 52 фото, 6 шрифтов, скрипт сцены, манифесты) лежат на `verdant-assets.lilkutabare.workers.dev`, превью заказчику — на `verdant-preview.lilkutabare.workers.dev`. Это Cloudflare.
- **Cloudflare в России с 09.06.2025 режут после первых ~16 КБ** (подтвердила сама Cloudflare; Ростелеком, МегаФон, Билайн, МТС, МГТС). Ошибки нет — файл просто не догружается. Кадр пролёта весит 50–190 КБ, то есть у русского без VPN пролёт и фото не придут. Владелец ходит через VPN и этого не видит; «всё фризит» у заказчика может быть отсюда.
- **GitHub в России с мая 2026 открывается хуже** (OONI: 10–16 % неудачных подключений 5–6 мая; в июле — перестал открываться в 30 городах). Как основной хостинг для России не годится.
- Бот заявок тоже на workers.dev. Заявка маленькая (запрос ~1 КБ, ответ ~100 Б), под порог 16 КБ проходит — но это не гарантия.

## 2. Решение — хранилище файлов Тильды

Проверено 21.10 на живом xtcpay.me:
- `static.tildacdn.com` → EdgeCenter, российский CDN (узел в Москве, AS210756); за границей тот же CDN через EDGEAM (Ереван). С российских узлов check-host отвечает за 10–40 мс (Cloudflare и GitHub — 200–440 мс), из Германии 0,16 с, из США 1 с.
- Отдаёт `Access-Control-Allow-Origin: *` (сцене это нужно) и кеш 60 дней. Имя файла сохраняется: `static.tildacdn.com/tild<код>/<имя>`, но у каждого файла своя папка-код.
- Запасной хост самой Тильды — `static3.tildacdn.com` (Hetzner, Германия): её скрипт `tilda-fallback` при ошибке подменяет хост, путь тот же.
- Место — около 1 ГБ на сайт, картинка до 5 МБ, видео mp4/webm до 5 МБ. Наши файлы все меньше.
- Медиа живут там же, где страница: если сайт открылся — открылись и картинки.

Чего не знаем: принимает ли «Загрузка файлов» Тильды `.webp`, `.woff2`, `.json`, `.js`, `.mp4` как есть. Проверка — пробный набор `dist/tilda-media-test/` (6 файлов, по одному каждого типа): залить, открыть ссылки.

Если Тильда какие-то форматы не примет — запасной путь: российское объектное хранилище (Selectel или Yandex Object Storage) на `media.verdantestate.ru`, одна команда заливки, пути как сейчас. Нужен аккаунт с картой (заказчик или владелец) и живой домен.

## 3. Что делаю в коде после проверки

1. `tools/tilda-media.mjs --pack` → `dist/tilda-media/`: все файлы с уникальными плоскими именами (`scene-tall-00.jpg`, `stills-tariff-basic-l.webp`), отдельно список «новое с прошлой заливки» — чтобы с новыми рендерами доливать только их.
2. Владелец заливает папку в Тильду (или я — через его Chrome, когда он вошёл), выделяет страницу со списком файлов и копирует в файл; `tools/tilda-media.mjs --map <файл>` вытаскивает ссылки → `docs/media-map.json`.
3. Сборка для Тильды подставляет адреса из карты вместо `__BASE__…`; сцена получает адреса кадров из карты.
4. Загрузчик кадров: не пришло за 4 с — тот же путь с `static3.tildacdn.com`. По `addEventListener`, не `onerror` (Тильда затирает `onerror`, см. память XTC).
5. Скрипт сцены (13 КБ) и манифесты — внутрь блоков, без отдельных файлов. Шрифты — в хранилище Тильды или её раздел шрифтов.
6. Форма: если бот не ответил за 8 с — показать кнопки WhatsApp и Telegram с уже набранным текстом заявки, чтобы клиент не потерялся.
7. Превью заказчику — страница на Тильде (её адрес `*.tilda.ws` или домен), а не workers.dev.
8. Проверка: стенд `dist/remote.html` с картой, матрица устройств, пролёт по шагам.
