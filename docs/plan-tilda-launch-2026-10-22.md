# План: запуск на Тильде блоками (22.10.2026)

Цель владельца: весь сайт живёт на Тильде блоками T123 (HTML-код), заявки уходят заказчику в Telegram через бота, медиа лежат на нашем хостинге, юридически всё на месте. Параллельно — плавность (`docs/plan-smooth-premium-2026-10-22.md`), мобильные рендеры и улучшение остальных элементов.

Правила владельца (не нарушать): одна правка — один коммит, снимки до/после, технику дизайна без запроса не менять, мастера в «все рендеры/» только читать, без веера агентов, решать самому, отвечать коротко. Пароли и токены не вводить никогда: черновик Тильды под паролем не открывать, токен бота владелец ставит сам.

## 1. Что делаем по команде «Go» — по порядку, без владельца

1. **Публичный хостинг медиа.** Cloudflare Pages проект `verdant-assets` на аккаунте lilkutabare (wrangler залогинен): `npx wrangler pages deploy docs/site --project-name verdant-assets`. В корень положить `_headers` с `Access-Control-Allow-Origin: *` (сцена грузит кадры с `crossOrigin='anonymous'`) и долгим кешем для медиа (`Cache-Control: public, max-age=31536000, immutable` — адреса и так с `?v=`). В `tools/build.mjs` поменять `PAGES_BASE` на `https://verdant-assets.pages.dev/`. Проверить: кадр, луп, шрифт отдаются с нужным заголовком. Оформить командой `node tools/deploy.mjs --assets` (добавить флаг), чтобы владелец мог повторять.
   - Риск: `*.pages.dev` и `*.workers.dev` из России иногда режут. Когда у заказчика будет домен на Cloudflare — переехать на `media.<домен>` одной правкой `PAGES_BASE`.
2. **Стенд Тильды.** Пересобрать, открыть `dist/preview.html` на стенде (`node tools/serve.mjs`, путь `/dist/preview.html`), прогнать матрицу 20 устройств по стенду и пролёт хиро по шагам — блоки внутри обёрток `.t-rec/.t123` должны вести себя как на превью. Отдельно проверить в обёртках: `position: sticky` хиро и ленты сезона (у Тильды бывает `overflow` на обёртках), `html{scroll-behavior:smooth}` и `scroll-padding-top` (не конфликтуют ли с меню Тильды), фиксированная шапка поверх Тильды.
3. **Лист заливки.** `tools/tilda-sheet.mjs` → `dist/ЗАЛИТЬ.html` (в git не идёт): одна страница, по кнопке «Копировать» на HEAD и на каждый блок 01–15 в порядке страницы, файл из `dist` байт в байт, номер сборки сверху, отметка «залито» у строк (localStorage). Образец — лист XTC (`~/Documents/xtc/@xtcpayme/shop-core/upload-helper.mjs`, память `tilda-upload-sheet-and-live-check`). Плюс короткая инструкция на листе: новая страница → настройки страницы без шапки и подвала Тильды, HEAD — в «Настройки сайта → Ещё → HTML-код для вставки внутрь head», каждый блок — отдельный T123, отступы блоков 0, порядок 01→15.
4. **Сервер заявок (решение владельца — Telegram-бот).** Воркер `verdant-form` на Cloudflare: `POST /lead` принимает JSON формы, проверяет (имя, телефон 11 цифр, согласие, honeypot-поле, ограничение частоты по IP), шлёт сообщение в Telegram через Bot API заказчику. `chat_id` получает сам: вебхук бота на `/tg`, на `/start` от разрешённого username (заказчик) сохраняет `chat_id` в KV и отвечает «Заявки с сайта будут приходить сюда». CORS только для домена сайта и `*.tilda.ws`. В `src/14-form.html` проставить `data-endpoint`. Токен бота **владелец** создаёт в @BotFather и ставит сам: `npx wrangler secret put BOT_TOKEN` (в чате токен не просить и не вводить). Дать владельцу две короткие команды: поставить токен и включить вебхук.
   - Риск, о котором владелец предупреждён: с 1.07.2025 первичный сбор ПДн граждан РФ в иностранные базы запрещён, Telegram иностранный. Если владелец решит снять риск — тот же код переносится в Yandex Cloud Functions (сохранение заявки в России, копия в Telegram). Без его слова не делать.
5. **Юридические страницы — заготовки с метками.** `src/legal/policy.html` и `src/legal/consent.html` (отдельные страницы Тильды, тоже T123), шрифты и стиль сайта. В тексте — места для данных заказчика в виде `[[ИНН]]`, `[[ОГРНИП]]` и т. п. + `tools/legal-fill.mjs`, который подставит данные из `docs/client-data.json`, когда заказчик ответит. Содержание политики: оператор и контакты, цели (обратная связь по заявке, расчёт, договор), состав данных (имя, телефон, площадь, что на участке, комментарий, технические данные и cookie), правовые основания, сроки хранения, передача (Telegram как канал доставки — указать), права субъекта и порядок обращения (10 рабочих дней), меры защиты. Согласие — отдельный документ (требование с 1.09.2025): конкретные цели, перечень данных, срок, порядок отзыва.
   - В форме: чекбокс «Даю согласие на обработку персональных данных» со ссылкой на страницу согласия и отдельная ссылка на политику; в подвале — ссылка на политику и строка реквизитов `[[Наименование]] · ИНН [[ИНН]] · ОГРН[ИП] [[ОГРН]]`. Пометка у прайса и тарифов: «Цены указаны для ориентира и не являются публичной офертой». Cookie-строка: ссылка «Подробнее» → политика.
   - Помечать на сайте, что тексты — черновик до проверки юристом, пока заказчик их не подтвердит.
6. **Плавность.** Продолжить по `docs/plan-smooth-premium-2026-10-22.md`: №1–7 сделаны, №8 ждёт записи экрана с айфона — попросить у владельца одной строкой и разобрать `python3 tools/rec-frames.py`.
