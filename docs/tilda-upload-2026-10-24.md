# Заливка в Тильду — что и куда грузить владельцу (24.10.2026, вечер)

Цель: сайт целиком живёт в Тильде, медиа — на GitHub Pages репозитория `verdantestate` в полном качестве (решение владельца 24.10). На тарифе Тильды владельца раздела «Загрузка файлов» нет (только Business), поэтому в саму Тильду медиа не грузятся. Заставка сайта держит страницу, пока медиа не загружены целиком, и показывает честный процент.

## Шаг 1. Медиа на GitHub Pages

1. На GitHub (аккаунт lilkutabare-hue) создать **пустой публичный репозиторий `verdantestate`** — без README, без .gitignore, без лицензии. Больше ничего не настраивать.
2. Сказать мне «создал». Я делаю `git push -u origin main` — удалённый адрес уже прописан, уедет около 170 МБ медиа плюс история.
3. В репозитории: **Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: main, папка /docs → Save.** Через 1–3 минуты откроется `https://lilkutabare-hue.github.io/verdantestate/`. Это и есть адрес из `docs/media-base.txt`, блоки для Тильды уже собраны с ним.
4. Проверка: открыть `https://lilkutabare-hue.github.io/verdantestate/site/media/scene/flight-tall.mp4` — файл должен отдаваться; в терминале `curl -I` на него даёт 200 и `access-control-allow-origin: *`.

Запасной путь, если GitHub у заказчика в России откроется плохо, — хранилище Яндекса с теми же путями (`tools/media-sync.sh`, ключ в `deploy/.s3env`, описание в журнале 24.10). Переключение — одна строка в `docs/media-base.txt` и `node tools/build.mjs`.

## Шаг 2. HEAD сайта

**Настройки сайта → Ещё → HTML-код для вставки внутрь head** (в разделе «Ещё» это ниже, после RSS) → вставить содержимое `dist/head.html` целиком, копируется кнопкой с листа `dist/ЗАЛИТЬ.html`. Один раз на сайт. Делать после шага 1.

## Шаг 3. Главная страница

1. Страница с адресом `/` (главная). Настройки страницы: без шапки и подвала Тильды.
2. Пятнадцать блоков **T123 (HTML-код)** подряд по листу: 01 шапка … 15 подвал. Отступы каждого блока сверху и снизу 0. Код не править внутри Тильды.
3. Опубликовать. После публикации один раз Cmd+Shift+R — Тильда и браузер кэшируют HEAD.

## Шаг 4. Страницы /policy и /consent

Две страницы с этими адресами, на каждой один блок T123 с листа (П и С). Шапку и подвал Тильды выключить. Реквизиты появятся, когда заказчик пришлёт данные.

## Шаг 5. Настройки сайта

- **Фавикон:** Настройки сайта → Главное → Favicon → Загрузить файл → `docs/site/favicon.ico` (или `docs/site/favicon-32.png`). Тильда принимает только ico/png/jpeg; svg и иконка iPhone (`docs/site/apple-touch-icon.png`) — по ссылке «здесь» в том же разделе.
- **Главная страница → SEO:** заголовок «Verdant Estate — уход за частными садами в Москве и области», описание «Постоянное управление садом: один договор, один ответственный, весь сад под контролем», картинка для соцсетей — `docs/site/media/scene/poster-wide.webp` (если не примет webp — пришлю jpg).
- **Домен:** зарегистрировать verdantestate.ru (21.10 в реестре его не было), затем Настройки сайта → Домен, DNS по инструкции Тильды. До домена — адрес на tilda.ws.
- **Шрифты** Тильды не трогать: сайт свои грузит сам.

## Шаг 6. Бот заявок

Заказчик открывает @VerdantEstateServiceBot, нажимает Start, шлёт `/test`. Потом тестовая заявка с опубликованной страницы. Если ник заказчика другой — сказать мне, поправлю `ALLOW_USER` и передеплою `verdant-form`.

## Шаг 7. Живая проверка (делаю я после твоего «залил»)

Сверка живой страницы со сборкой, матрица устройств на живом адресе, консоль, вес на 4G, запись с iPhone.

## Что уже готово к этому

- `dist/ЗАЛИТЬ.html` — лист с кнопками «Копировать» на HEAD и каждый блок, номер сборки, отметки «залито».
- `docs/media-base.txt` — адрес хостинга медиа; блоки собраны с ним.
- Скрипт сцены и манифесты вшиты в HEAD и блок хиро, отдельные .js и .json на хостинге не нужны.
- Пролёт — цельное видео полного качества (21 и 23 МБ); заставка ждёт его целиком и показывает процент; если поток не идёт 8 секунд, сцена переходит на кадры.
